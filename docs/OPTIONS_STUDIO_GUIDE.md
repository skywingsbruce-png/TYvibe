# Options Studio 使用指南（非技术版）

这份指南用大白话解释怎么用 Options Studio 复盘自己的美股期权持仓。
**它是只读的研究工具：不会下单，不会改动你的账户，也不构成投资建议。**

本文所有数字和标的都是**虚构示例**，只为说明界面含义。

---

## 一、把报表导进来

1. 在 IBKR 后台导出 **Activity Statement（活动报表）**，格式选 **CSV**。
2. 把文件存成 `data/private/ibkr_statement.csv`。
   这个目录已经被 git 忽略，**你的真实报表不会进入代码仓库**。
3. 刷新页面 `http://127.0.0.1:8899/options-studio`，或者跑一次命令行复盘：

```bash
cd agent && python -m cli options-studio review --file ../data/private/ibkr_statement.csv
```

生成的报告写在 `data/private/outputs/`，同样不会进仓库。

如果你还没放报表，界面会用一份**虚构样例**运行，并明确标注 "SAMPLE"。

---

## 二、看策略表

系统会把零散的期权腿**配对成策略**，而不是一条条孤立地看。比如「买一张远期
call + 卖一张近期同行权价 call」会被识别成一个**日历价差**，而不是「一个多头
call」加「一个裸卖 call」。这个区别很关键：真正的裸卖 call 风险无上限，而被远
期多头 call 覆盖的近期空头 call 不是。

能识别的类型包括：PMCC（穷人的备兑）、牛市看跌价差（bull put）、牛市看涨价差
（bull call）、日历价差、对角价差、备兑开仓、现金担保看跌、LEAPS 等。

> **识别不了就不猜。** 无法有把握归类的组合会标成 `unclassified`，而不是硬安一
> 个名字给你。看到它，说明需要你自己人工确认。

表格里每行的含义（虚构示例）：

| 列 | 例子 | 意思 |
|---|---|---|
| Strategy | `Calendar Call Spread` | 识别出的策略类型 |
| DTE | `60` | 最近一条腿还有多少天到期 |
| Max loss | `EUR -1,200.00` | 到期时最大亏损（静态可算的才有数字） |
| Max profit | `unbounded` | 无上限（比如单纯持有多头 call） |
| Max loss / profit | `approximate` | 属于时间价差，**算不出精确值**，见下一节 |
| 标签 | `assign/margin` | 该仓位有被行权 / 保证金风险，需要你留意 |

## 三、看三个风险数字（最重要）

首页会显示**三个分开的金额**。它们**不能相加理解成同一个「总风险」**，各自含义不同：

### 1. Deterministic defined max loss（严格定义风险）

例：`EUR 8,000.00`

这是**精确可算**的那部分。比如一个牛市看涨价差，买 100 行权价、卖 105 行权价、
净付出 300，那最大亏损就是 300，跟未来行情无关，不需要任何实时报价。垂直价差、
多头 call/put、备兑、现金担保看跌都属于这一类。

### 2. Time-spread net-debit proxy（时间价差净借方代理）

例：`EUR 5,000.00`（标注 approximate）

PMCC、日历、对角这类**两条腿到期日不同**的组合，**没法**用「到期日内在价值」算
出真实最大亏损——因为近腿到期那天，远期多头 call 还剩多少时间价值，必须有真实
期权报价和 IV 才知道。

所以这里**不编一个假数字**，而是用**你实际付出的净借方成本**作为保守的资金占用
代理。比如一个 PMCC 净付出 3,500，就按 3,500 计入。

> ⚠️ 这是**风险代理，不是精确最大亏损，也不是报价或保证金数据**。真实亏损可能
> 与它不同。

如果某个时间价差是**净收入（net credit）**或者**缺少成本数据**，那连代理都算不
出来。系统**不会当成零风险**，而是单独列成 `indeterminate`（不可估计）并至少给
一个 WATCH 提醒。

### 3. Combined risk proxy（组合风险代理）

例：`EUR 13,000.00`

前两者相加。**只用来排集中度和敞口大小**，界面上明确标注「不是精确最大亏损」。

集中度（哪个标的占比过高）就是按这个口径算的——如果只按第 1 项算，时间价差占用
的资金会凭空消失，让组合看起来比实际安全。

## 四、读 ALLOW / WATCH / BLOCK

每条规则会给一个结论：

| 结论 | 含义 |
|---|---|
| **ALLOW** | 这条规则下没问题 |
| **WATCH** | 需要你留意，但不阻止。**复盘已有持仓时**，仓位超过你的单笔偏好只会是 WATCH——你不可能被「禁止」持有已经在手的仓位 |
| **BLOCK** | 结构性问题。比如真正的裸卖 call（亏损无上限）、有仓位没解析出来（风险汇总不完整）、或误开了真实交易开关 |

**复盘（review）和拟议交易（propose）判定标准不同**，这是刻意的：

- **复盘已有持仓**：超过单笔上限 → WATCH
- **拟议一笔新交易**：超过单笔上限 → **BLOCK**（还没建仓，该拦就拦）

时间价差也**逃不过**单笔上限检查：它会用上面第 2 项的净借方代理来比对你的上限。
如果连代理都算不出来（净收入或缺成本），拟议模式下会**失败即拦截（BLOCK）**，
而不是因为「算不出来」就放行。

拟议交易卡只是一张**规则检查结论**，不会真的下单。

## 五、目前拿不到、也不会伪造的东西

以下内容会显示成 **unavailable（不可用）**，而不是编一个数出来：

- **Greeks（Delta/Gamma/Theta/Vega）**——需要真实现货价和真实 IV。没有配置真实
  行情源时一律不可用，**绝不会用猜的 IV 反推**。
- **实时行情 / 现价**——本工具不联网抓行情。
- **情景损益（-20% ~ +20%）**——需要真实现货价，同上。
- **保证金占用与购买力**——报表里没有可靠字段，**未经验证，不显示**。
- **时间价差的精确最大亏损**——原因见第三节第 2 点。
- **行权 / 指派后的持仓重建**——报表里有成交记录，但系统不会据此反推推测持仓。

看到 `unavailable`，意思是「**这项数据我没有，所以我不说**」，不是「这项为零」。
这是刻意的设计：宁可留白，也不给你一个看起来精确、实际靠猜的数字。

---

## 六、几条使用提醒

- 报表是**某一天的快照**。行情变了，风险也会变，需要重新导出复盘。
- 集中度按上面第 3 项口径算，看到某个标的占比很高时，记得它包含了时间价差的资金占用。
- **永远不要**把真实报表、账号、持仓、现金余额或聊天记录提交进代码仓库——包括写
  在注释或测试用例里。仓库里所有样例都是虚构的。
- 这个工具帮你**看清已有风险**，不替你做决定，也不构成投资建议。
